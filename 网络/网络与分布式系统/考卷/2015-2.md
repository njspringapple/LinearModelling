## III. CIDR und Subnetting / CIDR 与子网划分

### 6. IPv6-Adresse kürzen / 缩写 IPv6 地址

**Aufgabe / 题目**

> Notieren Sie die IPv6-Adresse  
> `1337:0000:0000:0000:1000:0000:0000:0001`  
> maximal verkürzt.

**Lösung / 解答**

```text
1337::1000:0:0:1
```

**Erklärung / 说明**

- Die längste zusammenhängende Nullfolge ist `0000:0000:0000`。
- Diese wird durch `::` ersetzt。
- Führende Nullen in Blöcken werden entfernt。

中文：最长的连续零块是中间的三个 `0000`，用 `::` 压缩；其他块去掉前导零。

### 7. IPv6-Subnetting / IPv6 子网划分

**Aufgabe / 题目**

Ein Internetanbieter erhält das Subnetz:

```text
2001:CDE0:0000:0000:0000:0000:0000:0000/28
```

Dieses wird vollständig in vier gleich große Teilbereiche geteilt.

一个 ISP 得到子网 `2001:CDE0::/28`，将其完整分成四个等大的子网。

#### 7a. Länge der Netz-ID / 子网前缀长度

Vier gleich große Teilnetze bedeuten:

$4 = 2^2$

Es werden also **2 zusätzliche Bits** benötigt.

$28 + 2 = 30$

**Antwort / 答案：**

```text
/30
```

中文：分成 4 个子网需要增加 2 位，因此新前缀是 **/30**。

---

#### 7b. Vier entstehende Subnetze / 四个子网

Ausgangsnetz:

```text
2001:CDE0::/28
```

Bei `/28` liegen die relevanten Bits im zweiten Hextett.  
Die vier `/30`-Subnetze sind:

```text
2001:CDC0::/30
2001:CE00::/30
2001:CE40::/30
2001:CE80::/30
```

**Hinweis / 说明**

Das gegebene Netz `2001:CDE0::/28` ist keine saubere Netzadresse für `/28`, weil bei `/28` die letzten 4 Bits des zweiten Hextetts Hostbits sind. Die tatsächliche `/28`-Netzadresse ist:

```text
2001:CDC0::/28
```

Daher lauten die vier korrekten `/30`-Teilnetze wie oben.

中文说明：  
`2001:CDE0::/28` 对 `/28` 来说不是规范网络地址，因为第二个 hextet 的后 4 位属于主机位。将其归一化后的网络地址是 `2001:CDC0::/28`，再划分成四个 `/30` 子网。

### 8. IPv6 Fragmentierung / IPv6 分片

Gegeben / 已知：

```text
E1 --2500 Bytes-- R1 --280 Bytes-- R2 --1500 Bytes-- E2
```

---

#### 8a. Wer fragmentiert ein 1000-Byte IPv6-Paket von E1 nach E2?

**Deutsch:**  
Bei IPv6 fragmentieren **Router nicht**. Nur der Sender, also **E1**, darf fragmentieren.  
Da auf dem Pfad eine MTU von **280 Bytes** existiert, ist ein 1000-Byte-Paket zu groß.

**Antwort:**

```text
E1
```

中文：IPv6 中路由器不负责分片，只能由源主机分片。因此是 **E1** 分片。

---

#### 8b. IPv6-Paket mit 600 Byte Nutzdaten / 600 字节载荷的 IPv6 包分片

Gegeben:

```text
IPv6 Header: 40 Byte
Nutzdaten:   600 Byte
```

Hinweis:

```text
IPv6 Header inkl. Fragmentation Header = 48 Byte
```

Kleinste MTU auf dem Pfad:

```text
280 Byte
```

Maximale Nutzdaten pro Fragment:

280−48=232280 - 48 = 232280−48=232

IPv6-Fragmentnutzdaten außer dem letzten Fragment müssen Vielfache von 8 Byte sein.  
`232` ist durch 8 teilbar:

232/8=29232 / 8 = 29232/8=29

Also:

```text
Fragment 1: 48 Byte Header + 232 Byte Nutzdaten = 280 Byte
Fragment 2: 48 Byte Header + 232 Byte Nutzdaten = 280 Byte
Fragment 3: 48 Byte Header + 136 Byte Nutzdaten = 184 Byte
```

|Fragmentnummer|Deutsch|中文|
|--:|---|---|
|1|Header 48 Byte + Nutzdaten 232 Byte = 280 Byte|头部 48 字节 + 数据 232 字节 = 280 字节|
|2|Header 48 Byte + Nutzdaten 232 Byte = 280 Byte|头部 48 字节 + 数据 232 字节 = 280 字节|
|3|Header 48 Byte + Nutzdaten 136 Byte = 184 Byte|头部 48 字节 + 数据 136 字节 = 184 字节|

## IV. Vielfachzugriff / 多路访问

Gegeben:

- A möchte 3 Rahmen an B senden.
- B möchte 3 Rahmen an C senden.
- C möchte 3 Rahmen an A senden.
- Statischer Zeitmultiplex.
- Alle sind gleichzeitig sendebereit.
- Pro Zeitintervall kann genau ein Rechner senden.

已知：A、B、C 各自要发送 3 个帧；采用静态时分复用，每个时间片只能一个主机发送。

---

### 9. Zeitstrahl / 时间轴

Bei statischem Zeitmultiplex werden die Intervalle gleichmäßig verteilt:

```text
A | B | C | A | B | C | A | B | C
```

中文：静态时分复用中，发送机会按固定顺序轮流分配。

---

### 10. Quittungen / 确认帧 ACK

每个数据帧发送后，接收方会尽快发送一个显式确认 PDU，长度与被确认的数据帧相同，即也占一个时间片。  
没有传输错误。

Datenübertragungen / 数据帧：

```text
A -> B : 3 Datenrahmen
B -> C : 3 Datenrahmen
C -> A : 3 Datenrahmen
```

Quittungen / ACK：

```text
B -> A : 3 ACKs
C -> B : 3 ACKs
A -> C : 3 ACKs
```

总帧数：

9+9=189 + 9 = 189+9=18

#### 10a. Wie viele Rahmen sind notwendig?

```text
18 Rahmen
```

中文：共需要 **18 个帧**。

---

#### 10b. Von welchem PDU-Typ ist der letzte gesendete Rahmen?

Da nach jedem Datenrahmen eine Quittung erforderlich ist, der letzte gesendete Rahmen ist eine:

```text
Quittungs-PDU / ACK
```

中文：最后一个帧是 **确认帧 ACK**。

---

#### 10c. Letzter Rechner und Empfänger

Wenn A als erster mit der Datenübertragung beginnt, ergibt sich bei statischem TDM eine mögliche Reihenfolge:

```text
A->B Daten
B->A ACK
C->A Daten
A->B Daten
B->A ACK
C->A Daten
A->B Daten
B->C Daten

C->B ACK
A->C ACK

```

Der letzte Rahmen ist:

```text

```

**Antwort / 答案：**

```text

Empfänger: B
```

## V. Ethernet, CSMA / 以太网与 CSMA

### 11. Minimale Rahmengröße / 最小帧长

Gegeben:

```text
Datenrate R = 10 GBit/s = 10^10 Bit/s
Leitungslänge d = 2000 m
Signalausbreitung v = 2 * 10^8 m/s
```

One-way propagation delay:

$t = \frac{d}{v} = \frac{2000}{2 \cdot 10^8} = 10^{-5}s$

Round-trip time:

$2t = 2 \cdot 10^{-5}s$

Minimale Rahmenlänge für CSMA/CD:

$L = R \cdot 2t$

$L = 10^{10} \cdot 2 \cdot 10^{-5} = 2 \cdot 10^5 \text{ Bit}$

$200000 \text{ Bit} = 25000 \text{ Byte}$

**Antwort / 答案：**

```text
25000 Byte
```

中文：为了在最坏情况下仍能检测碰撞，最小帧大小为 **25,000 字节**。

### 13. CRC für Wort `11 00 11`

Nachricht:

```text
110011
```

Generator:

```text
1001
```

Grad des Polynoms:

```text
3
```

Also werden 3 Nullen angehängt:

```text
110011000
```

Modulo-2-Division durch `1001` ergibt Rest:

```text
010
```

Zu sendende Bitfolge:

```text
110011010
```

中文：CRC 校验位是 `010`，因此发送比特串是：

```text
110011010
```

---

### 14. Empfangene Bitfolge `10 01 10 01`

Empfangen:

```text
10011001
```

Generator:

```text
1001
```

Modulo-2-Division:

```text
10011001 ÷ 1001
```

Da:

```text
10011001 = 1001 · 10001
```

Rest:

```text
000
```

**Antwort / 解答：**

Die Übertragung wird als fehlerfrei erkannt, weil der Divisionsrest `000` ist.

中文：接收方用生成多项式 `1001` 去除收到的比特串，余数为 `000`，因此认为传输无错。  
接收方知道无错的位置在 **CRC-Prüfung / CRC 校验处**，也就是除法余数为 0 时。

### 22. Wird E-Mail durch TCP unempfindlich gegenüber Datenverlust?

**Kurzantwort / 简答：**

```text
Nein, nicht vollständig.
```

**Begründung / 理由：**

TCP sorgt auf Transportebene für zuverlässige Übertragung zwischen zwei direkt kommunizierenden Mail-Servern oder zwischen Client und Server.  
Aber E-Mail ist ein Store-and-Forward-System. Nach erfolgreicher TCP-Übertragung können Mails trotzdem verloren gehen, z. B. durch Serverfehler, falsche Adresse, Mailbox-Quota, Spamfilter oder administrative Löschung.

中文：TCP 只保证当前连接中的字节流可靠传输，不保证整封邮件端到端永不丢失。
