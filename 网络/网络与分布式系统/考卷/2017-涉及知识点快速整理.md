
## ⚠️ 关于 OSI 模型层数的重要纠错

聊天里记的是 **5 层**（物理+链路+网络+传输+应用），但**标准 OSI 模型（OSI-Modell）是 7 层**。你老师给的其实是简化记忆版（更接近 TCP/IP 模型）。考试若考完整 OSI，缺的两层是：

- **会话层（Sitzungsschicht / Session Layer）**
- **表示层（Darstellungsschicht / Presentation Layer）**

**完整 7 层从下往上：** 物理 → 链路 → 网络 → 传输 → 会话 → 表示 → 应用

---

## 一、OSI 模型（OSI-Modell）— 必考

| 层   | 中文（德语 / 英语）                                  | 关键字                              |
| --- | -------------------------------------------- | -------------------------------- |
| 1   | 物理层（Bitübertragungsschicht / Physical Layer） | 传输介质（Übertragungsmedium）：网线、WiFi |
| 2   | 链路层（Sicherungsschicht / Data Link Layer）     | MAC 地址（MAC-Adresse）              |
| 3   | 网络层（Vermittlungsschicht / Network Layer）     | IP 地址（IP-Adresse）                |
| 4   | 传输层（Transportschicht / Transport Layer）      | 端口号（Portnummer）                  |
| 7   | 应用层（Anwendungsschicht / Application Layer）   | —                                |

### 设备与所属层

- **路由器（Router）**：圆形图标，负责 1–3 层；内部配置**路由表（Routing-Tabelle）**，用 IP + 掩码（Maske）方式
- **交换机（Switch / Vermittlungsknoten）**：方形图标
    - 二层交换机：只负责 1–2 层，基于 MAC 地址转发（Weiterleitung）
    - 三层交换机：需到网络层

---

## 二、传输层（Transportschicht）

- **任务**：端到端通信（Ende-zu-Ende-Kommunikation）✅ 正确
- **UDP（User Datagram Protocol / Benutzer-Datagramm-Protokoll）**：不可靠（unzuverlässig）、快速、简单、开销小（geringer Overhead / geringer Mehraufwand）
- **TCP（Transmission Control Protocol / Übertragungssteuerungsprotokoll）**：可靠（zuverlässig）、复杂、开销大 —— 因带确认（Bestätigung / ACK）和建链（Verbindungsaufbau）
- **套接字（Socket / Sockel）**：属传输层。通信需创建 socket，指定 UDP/TCP
    - 伪代码：`mySocket = udp(172.0.0.100, 12000)`

---

## 三、面向连接与相关协议

- **面向连接（verbindungsorientiert）** = TCP（属传输层）
    - **面向差错（CRC 校验 / CRC-Prüfung）**
    - **确认机制（ACK / Bestätigung）**
- **DHCP（Dynamic Host Configuration Protocol / Dynamisches Host-Konfigurationsprotokoll）**：连 WiFi 或插网线后，由 DHCP 服务器（一般内置于路由器）**动态分配（dynamische Zuteilung）** IP 地址
- **滑动窗口（Sliding Window / Schiebefenster / Gleitfenster）**：批量发送数据后统一等 ACK，避免"发一个等一个"
    - 口诀：滑动窗口 = 高速传输大量数据（Hochgeschwindigkeits­übertragung großer Datenmengen）
- **拥塞窗口（Congestion Window / Überlastfenster / Staufenster）**：自动探测网络与对方的最大传输能力（那条曲线）

---

## 四、网络层协议与 IP 报文

- **ICMP（Internet Control Message Protocol / Internet-Steuerungsnachrichtenprotokoll）**：ping 探测**网络连通性（Netzwerkerreichbarkeit / Konnektivität）**、**时延（Verzögerung / Latenz）**、**丢包率（Paketverlustrate）**，属**第 3 层网络层**
    - IP 报文（IP-Paket）与 ICMP 报文是两个独立报文
    - IP 报文的**载荷（Nutzlast / Payload）** 可为 TCP/UDP；ICMP 无载荷
- **MTU 最大传输单元（Maximum Transmission Unit / Maximale Übertragungseinheit）**：必考，属 IP 层。不同网络 MTU 不同 → 需**分片（Fragmentierung）**
- IP 包头需指示载荷是 TCP 还是 UDP（Protokollfeld），便于**解包（Entkapselung）** 后分发

### IP 包头字节数（计算题高频）

- **IPv4 包头（IPv4-Header）**：20 字节（不含选项 / ohne Optionen）
- **IPv6 包头（IPv6-Header）**：40 字节（考试易混淆）

---

## 五、IPv6 特性

- IPv6 包头**没有校验和（keine Prüfsumme）**（与 IPv4 不同）
- IPv6 设计考虑了 **QoS 服务质量（Quality of Service / Dienstgüte）**
- IPv4/IPv6 都可用 **CIDR（Classless Inter-Domain Routing / Klassenloses Routing）** 描述

---

## 六、自治系统与路由协议

- **自治系统（AS / Autonomes System）**：把一堆计算机、路由器、交换机划到一个 AS
- **AS 内部 = IGP（Interior Gateway Protocol / Internes Gateway-Protokoll）**：
    - **RIP（Routing Information Protocol）**
    - **OSPF（Open Shortest Path First）**：在 AS 内部路由器间同步全量**链路状态（Verbindungszustand）**（连通、丢包、时延）
- **AS 之间 = BGP（Border Gateway Protocol / Grenz-Gateway-Protokoll）**

---

## 七、TCP 拥塞控制

- TCP 特点：开销（Overhead）、可靠性（丢包重传 / Neuübertragung）、序列号（Sequenznummer）
- **初始门限（ssthresh / Schwellenwert）**：指数增长与线性增长的分界；因**丢包（Paketverlust）** 或**超时（Zeitüberschreitung / Timeout）** 减半或回归 1
- **慢启动（Slow Start / Langsamer Start）** = 指数增长（exponentielles Wachstum）
- **拥塞避免（Congestion Avoidance / Überlastvermeidung）** = 线性增长（lineares Wachstum）

### ⚠️ 重要纠错：拥塞控制 vs 流量控制

聊天第 9 题写"拥塞机制目的是保护接收方，防止接收缓冲区溢出" —— **这个说法把两个概念搞混了！**

- **流量控制（Flusssteuerung / Flow Control）**：保护**接收方缓冲区**，用**接收窗口（rwnd / Win）**。这才是"发送方不知道接收方能力、防止缓冲区溢出"的机制。
- **拥塞控制（Überlastkontrolle / Staukontrolle / Congestion Control）**：保护**网络本身**（防止网络中间节点拥塞），用**拥塞窗口（cwnd）**。

所以"发太快、接收人缓冲区溢出"描述的其实是**流量控制**，不是拥塞控制。考试务必分清。

### TCP-Tahoe vs TCP-Reno（收到 3 个重复 ACK / 3 dup ACK 时）

- **TCP-Reno**：窗口减半，进入线性增长（快速恢复 / Fast Recovery）
- **TCP-Tahoe**：窗口回归 1，进入指数增长（慢启动）

### 拥塞曲线（第 7 题）

- Y 轴：拥塞窗口大小（Größe des Überlastfensters）
- 三个阶段：慢启动、拥塞避免、（丢包后）恢复

---

## 八、NAT（网络地址转换）— 必考

- **NAT（Network Address Translation / Netzwerkadressübersetzung）**：家用路由器必用
    1. 解决 IP 地址不够（IPv4-Adressknappheit）
    2. 隐藏局域网拓扑（Topologie）
    3. 修改发送者 IP 和端口，否则接收方无法回传
- 将**私有地址（private Adresse）** 改为**公网地址（öffentliche Adresse）**
- ⚠️ 注意：修改的是**源 IP / 源端口（Quell-IP / Quellport）**，**不是**目的 IP / 目的端口
- 建议复习 PPT 中 NAT 部分

---

## 九、PDU / SDU / PCI 与对等层

- **PDU = SDU + PCI**
    - **PDU（Protocol Data Unit / Protokolldateneinheit）**：带头的完整包
    - **SDU（Service Data Unit / Dienstdateneinheit）**：载荷
    - **PCI（Protocol Control Information / Protokoll-Steuerinformation）**：控制头
- **对等层（Peer Layer / Partnerschicht）**：N —— N，如 N-1 —— N-1
- 传递方向：PDU 往下传（→ N-1）；SDU 往上传（→ N+1）
- 发送：从上往下；接收：从下往上

## 十、常用协议及所属层

|协议|所属层|功能|
|---|---|---|
|**ARP（Address Resolution Protocol / Adressauflösungsprotokoll）**|链路层|询问某 IP 对应的 MAC，同时广播（Rundsendung）自己的 MAC|
|**ICMP**|网络层|探测网络连通性|
|**DNS（Domain Name System / Domänennamensystem）**|应用层|域名（Domänenname）↔ IP|
|**OSPF**|网络层|AS 内部同步链路全量状态|

> ⚠️ 小提示：ARP 处于链路层与网络层之间（做 IP→MAC 映射），部分教材归为第 2 层，部分归为 2/3 层之间。按你老师的说法记链路层即可，但心里有数。

## 十二、DNS 域名解析细节

- 域名从右向左看（顶级域在右）：
    - **com** → 公司（Company / Firma）
    - **de** → 德国（Deutschland）
    - **cn** → 中国（China）
- **迭代查询（iterative Abfrage）**：客户端逐级问：先根 → de → lmu.de → ifi.lmu.de
- **递归查询（rekursive Abfrage）**：日常用这个，DNS 服务器帮你全程拆解并返回最终结果
- ⚠️ 补充：聊天里"日常我们用的是这个过程看不见"指的就是**递归**，请对应上术语

## 十四、广播地址计算（第 16 题）

**示例：`141.84.32.x /19`**

- `/19` = 2 字节（16 位）多 3 比特 → `141.84` 不动
- 第三字节 `32` → 二进制 `0010 0000`
- 剩余 `19 − 2×8 = 3` 比特 → `001` 为网络位不动；求**广播地址（Broadcast-Adresse / Rundsendeadresse）** 时后面全置 1 → `0011 1111`
- 快速转十进制：`0011 1111 = 0100 0000 − 1 = 64 − 1 = 63`
    - ⚠️ 纠错：聊天里先写成"64−1=64"是笔误，正确是 **63**
- 最后字节：广播地址 = 255，**网络地址（Netzadresse）** = 0
- 结果：`141.84.63.255`

## 十五、路由表与子网划分 — 几乎必考

- 每条链路标注所属子网（Subnetz）、每个端口（Port）标注 IP
- **规律：CIDR 数字越大 → 子网越小**
- 示例：`141.84.0.0 /19` 内再划分为 `/21`
    - 主机地址位（Hostbits）：`32 − 21 = 11`
    - `21 − 19 = 2` 比特 → 可划分 22=42^2 = 422=4 个 `/21` 小子网
    - 规律：2 比特 = 4 个子网，3 比特 = 8 个子网

---

## 十六、IPv6 压缩与子网

- **压缩规则**：把**最长的连续全 0 块**用 `::` 代替（且 `::` 全地址只能用一次）
    - `1337:0000:0000:0000:1000:0000:0000:0001` → `1337::1000:0000:0000:0001`
    - 前导 0 可省：`0000`→`0`，`0001`→`1`
- IPv6 用**十六进制（Hexadezimal）** 表示，子网划分原理同 IPv4，但别把进制搞错

---

## 十七、分片计算（第 6 题）

- 若数据 ≤ 链路最小 MTU → **无需分片**（送分题）
- IPv4 头 20 字节，每片载荷 = MTU − 20
    - 示例：`600 = 280 + 280 + 40`，分三片
- **MF（More Fragments / Weitere Fragmente）标志位**：
    - 1 = 还有后续分片
    - 0 = 最后一片（结束）

---

## 十八、TCP 序列号与窗口计算

- **ACK 返回序列号 = 接收到的序列号 + 数据大小（字节）**
- **Win（Receive Window / Empfangsfenster）**：接收缓冲区（Empfangspuffer）剩余可用字节
    - 示例：缓冲区 4096，收到 1024 → 反馈 `WIN = 4096 − 1024 = 3072`
- 缓冲区释放时机：应用层（Anwendungsschicht，传输层的上层）把数据读走后

---

## 十九、CRC 校验

- **CRC（Cyclic Redundancy Check / Zyklische Redundanzprüfung）**
- 发送方：算出**余数（Rest）** 后附在原数据末尾一起发送
- 接收方：重新做除法验证，**余数为 0 → 无差错**
