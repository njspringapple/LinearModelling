## Allgemeine Fragen / 一般问题

---

### Flusssteuerung / 流量控制

**定义：** 防止发送方发送速度超过接收方处理速度的机制。

TCP使用**滑动窗口**实现流量控制，接收方通过Window字段告知发送方可用缓冲区大小。

---

### Staukontrolle / 拥塞控制

**定义：** 防止网络过载的机制。

TCP拥塞控制算法：Slow Start, Congestion Avoidance, Fast Retransmit, Fast Recovery

---

### Distanzvektor-Routing → Count-to-Infinity → Gegenmaßnahme?

**距离向量路由 → 计数到无穷问题 → 对策？**

**问题：** 当链路断开时，路由器可能循环传递错误信息，距离不断增加。

**对策：**

- **Split Horizon / 水平分割：** 不向信息来源方向发送该信息
- **Poisoned Reverse / 毒性反转：** 向来源方向发送无穷大距离
- **Hold-down Timer：** 收到坏消息后等待一段时间
- **Maximum Hop Count：** 设置最大跳数（如RIP的15跳）

---

### Socket → 2-Tupel → Bestandteile?

**Socket → 2元组 → 组成部分？**

**Lösung / 答案：** **(IP-Adresse, Port-Nummer)**

一个完整的TCP连接由5元组标识：(源IP, 源端口, 目标IP, 目标端口, 协议)

---

### Wozu ARP?

**ARP的用途？**

**Lösung / 答案：** 将**IPv4地址**解析为**MAC地址**

当主机知道目标IP但不知道MAC地址时，发送ARP请求广播，目标主机回复其MAC地址。

---

### Wann Default Route v. Router?

**路由器何时使用默认路由？**

**Lösung / 答案：** 当路由表中**没有匹配**目标地址的特定路由时，使用默认路由（通常表示为0.0.0.0/0）。

---

### Welches Transportschicht mit DNS?

**DNS使用哪种传输层协议？**

**Lösung / 答案：**

- **UDP端口53：** 普通DNS查询（默认）
- **TCP端口53：** 区域传输、大响应（>512字节）

## IV. Elektrische Leiter v. Lichtwellenleiter

## 电导体 vs 光纤

---

### Störeffekte, welche bei elektr. aber nicht Lichtwellenleiter?

**电导体有但光纤没有的干扰效应？**

**Lösung / 答案：**

- **Elektromagnetische Interferenz (EMI) / 电磁干扰**
- **Übersprechen (Crosstalk) / 串扰**
- **Induktion / 感应**

光纤使用光信号，不受电磁干扰影响。

---

### Maßnahme um Eff. zu minimieren?

**减少这些影响的措施？**

**Lösung / 答案：**

- **Abschirmung / 屏蔽**（如屏蔽双绞线STP）
- **Verdrilllung / 绞合**（双绞线减少串扰）
- **Abstand vergrößern / 增加距离**

---

### Lichtwellenleiter: 2 Klassen (Kerndurchmesser) nennen

**光纤：列举两类（按纤芯直径）**

**Lösung / 答案：**

|类型|Kerndurchmesser|特性|
|---|---|---|
|**Multimode / 多模**|50-62.5 μm|短距离，较便宜|
|**Singlemode / 单模**|8-10 μm|长距离，高带宽|

---

### Wie ist eine Mode definiert?

**模式如何定义？**

**Lösung / 答案：** Mode是光在光纤中传播的**路径/角度**。单模光纤只允许一条路径，多模允许多条路径同时传播。

---

### Durch Dämpfung ist Reichw. v. Signalen (elektr. u. Licht) begrenzt.

### Nenne Netzkomponente d. Sch.1 um Reichw. zu erhöhen.

**由于衰减，信号传播距离有限。说出第1层的网络组件以增加距离。**

**Lösung / 答案：** **Repeater / 中继器** 或 **Verstärker / 放大器**

中继器接收弱信号，放大后重新发送。

## V. Carrier Sense Multiple Access (CSMA)

---

### 题目参数

- 64 Byte 帧
- 有效传输速率：10⁷ bit/s
- 传播速度：2×10⁸ m/s
- 理想介质无衰减

---

### (a) Wie groß max. Leitungslänge, um Kollision durch CSMA/CD erkennen zu können?

**能通过CSMA/CD检测碰撞的最大线路长度？**

**Lösung / 答案：**

**计算：**

1. 帧传输时间：  $t_{frame} = \frac{64 \times 8}{10^7} = \frac{512}{10^7} = 51.2 \mu s$
    
2. 最大往返时间：  

- $2 \times t_{prop} \leq t_{frame}$​  
- $t_{prop} \leq 25.6 \mu s$
    
3. 最大距离：  

- $d_{max} = 25.6 \times 10^{-6} \times 2 \times 10^8 = 5120 m = \textbf{5.12 km}$
    

---

### (b) Veränderung d. Leitungslänge durch Erhöhung d. Übertragungsrate?

**提高传输速率对线路长度的影响？**

**Lösung / 答案：** **最大线路长度减小**

传输速率增加 → 帧传输时间减少 → 可用于信号往返的时间减少 → 最大距离减小

## VI. Fehlererkennung & -korrektur

## 错误检测与纠正

---

### Paritätsbit für 1000001 (ungerade Parität)

**为1000001计算奇校验位**

**Lösung / 答案：**

- 数据：1000001
- 1的个数：2（偶数）
- 奇校验需要1的总数为奇数
- **Paritätsbit = 1**
- 完整数据：**10000011**

---

### Block Check Character für 1100101|00-11101（偶校验）

**消息的块校验字符**

**Lösung / 答案：**

BCC是对每一列进行偶校验：

```
1 1 0 0 1 0 1
0 0 1 1 1 0 1
--------------
1 1 1 1 0 0 0  (BCC)
```

每列1的个数加上BCC位后应为偶数。

---

### Hamming-Distanz H(C) = min({H(x,y) | x≠y ∀ x,y ∈ C})

**汉明距离公式**

**定义：** 码字集合C的汉明距离是任意两个不同码字之间比特差异的最小值。

---

### (a) Was ist Hamming-Distanz H von C? Wie viele verfälschte Bits können erkannt werden?

**C的汉明距离是多少？能检测多少位错误？**

|Code C|Hamming-Distanz H(C)|可检测的位错误数|
|---|---|---|
|Paritätsprüfung / 奇偶校验|2|1|
|BCC|2|1|

**公式：**

- 检测d位错误需要：H(C) ≥ d + 1
- 纠正d位错误需要：H(C) ≥ 2d + 1

---

### (b) Gibt es Übertr.Fehler die zuv. korrigiert werden?

**有可以可靠纠正的传输错误吗？**

对于简单奇偶校验（H=2）：**不能纠正任何错误**，只能检测奇数位错误。

**示例：**

```
发送: 1100101|0
接收: 1100101|0
BCC:  00000001
```

标记错误位。

## VII. Routing & IPv4-Multicasting

## 路由与IPv4多播

---

### Protokoll zum Gruppenmanagement?

**组管理协议？**

**Lösung / 答案：** **IGMP (Internet Group Management Protocol)**

主机使用IGMP加入/离开多播组，路由器使用IGMP了解哪些主机属于哪些组。

---

### 224.0.0.0/4 → wie viele IPv4 Adressen?

**224.0.0.0/4 包含多少个IPv4地址？**

**Lösung / 答案：**

- /4 表示4位网络前缀，28位主机部分
- 地址数量 = 2²⁸ = **268,435,456** 个地址
- 这是多播地址范围（D类地址）：224.0.0.0 - 239.255.255.255

---

### (a) Welche Router traversiert ein IPv4 Paket, wenn es vom Client C an Server S geschickt wird?

**从客户端C发送到服务器S的IPv4数据包经过哪些路由器？**

需要看具体网络拓扑图来回答。

---

### (b) Was passiert, wenn C IPv4 Paket an IPv4 12.23.34.45 sendet?

**当C向12.23.34.45发送IPv4数据包时会发生什么？**

12.23.34.45是一个**单播地址**（不是多播地址224-239开头），所以按正常单播路由处理。

---

### (c) Gegeben Multicast-Routing Algorithmus. Aufbasis dessen, welchen Weg wird Paket von S nach C nehmen.

**给定多播路由算法，从S到C的数据包走哪条路径？**

常见多播路由算法：

- **Reverse Path Forwarding (RPF)：** 数据包只从最短路径方向接受
- **PIM (Protocol Independent Multicast)**

---

### Ist aus ihrer Sicht TCP bei IPv4-Multicasting einsetzbar?

**您认为TCP可以用于IPv4多播吗？**

**Lösung / 答案：** **Nein / 不可以**

**理由：**

- TCP是**面向连接**的协议，需要在两个端点之间建立连接
- 多播是**一对多**通信，一个发送方向多个接收方发送
- TCP的三次握手、序列号、确认机制无法有效扩展到多个接收方
- **UDP**更适合多播，因为它是无连接的

## VIII. TCP Überlastkontrolle

## TCP拥塞控制

**图示：** 显示了典型的TCP拥塞窗口变化，包括timeout事件

---

### (a) y-Achse Beschriftung?

**Y轴标注？**

**Lösung / 答案：** **CongWin（拥塞窗口）** 或 **Segmente/MSS**

---

### (b) Phase a?

**阶段a是什么？**

**Lösung / 答案：** **Slow Start / 慢启动**

特点：窗口指数增长

---

### (c) Phase b?

**阶段b是什么？**

**Lösung / 答案：** **Congestion Avoidance / 拥塞避免**

特点：窗口线性增长（每RTT增加1个MSS）

---

### (d) Vervollst. Phase c

**完成阶段c的图**

阶段c是**timeout后的恢复**：

- cwnd重置为1
- ssthresh设为原cwnd的一半
- 重新进入Slow Start

---

### (e) Frühzeitiger Indikator für Paketverlust vor timeout?

**超时前的丢包早期指示器？**

**Lösung / 答案：** **3 Duplicate ACKs / 3个重复确认**

收到3个重复ACK表示可能丢包，触发Fast Retransmit而不等待超时。

---

### (f) Verfahren zur Optimierung d. Überlastkontrollalgorithmus nach timeout?

**超时后优化拥塞控制算法的方法？**

**Lösung / 答案：** **Fast Recovery / 快速恢复**

在3个重复ACK后：

- ssthresh = cwnd/2
- cwnd = ssthresh + 3（而不是重置为1）
- 直接进入Congestion Avoidance

### ADSL协议栈计算题

**场景：** 通过ATM模拟以太网的ADSL，使用PPPoE隧道建立TCP/IP连接

**协议栈：**

```
TCP/UDP (20B/8B) | 用户数据
----------------
IP-H (20B)
----------------
PPP-H (5B) | FCS (4B)
----------------
ETH-H (14B) | FCS
----------------
ATM-H (5B) | ATM负载 (48B) ...
```

---

### TCP 438B UD versenden → Wie viel Byte an Daten von ATM-Schicht sind an ADSL-Schicht zu übergeben?

**发送TCP 438B用户数据 → ATM层向ADSL层传递多少字节？**

**Lösung / 答案：**

**计算过程：**

1. TCP层：438B + 20B(TCP头) = 458B
    
2. IP层：458B + 20B(IP头) = 478B
    
3. PPP层：478B + 5B(PPP头) = 483B
    
4. 以太网层：483B + 14B(ETH头) + 4B(FCS) = 501B
    
5. ATM分片：
    
    - ATM负载 = 48B
    - 需要的ATM信元 = ⌈501/48⌉ = 11个信元
    - 每个信元 = 5B(头) + 48B(负载) = 53B
6. **总计 = 11 × 53 = 583B**
